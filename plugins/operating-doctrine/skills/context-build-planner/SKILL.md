# Context Build Planner

This skill inherits operating-doctrine and never overrides it. These independently authored instructions are a planning aid, not a recovered vendor package or a claim of exact original behavior.

## Boundaries

Read the live Organization Instructions, HQ Rulebook and newest applicable Decision Log entries before relying on company rules. Preserve the difference between source facts, proposed choices and unknowns. A brief grants no authority to build, publish, merge, deploy or contact anyone.

## Workflow

1. Identify the company, project owner, intended users and goal. Check the existing project and marketplace before proposing new work. Read authorized business and brand sources before asking for settled facts. Record each source and its version or retrieval date in the private brief.
2. Gather only decisions that change the brief. Cover required features, approved copy, pages or app flows, design references and explicit inclusions and exclusions. Ask about SEO migration when replacing an existing site. Do not impose a fixed interview sequence or invent missing business facts.
3. Separate confirmed requirements from suggestions and unresolved decisions. Never invent offers, proof, permissions or approved copy. Mark proposed copy as a draft. Missing nonessential detail stays visible without blocking a bounded brief.
4. Produce one reviewable V1 brief using the output structure below. A public fixture uses only supplied or observed public facts. A public code repository receives no private business context, private source identifiers or private links.
5. Stop at the brief unless further work is separately authorized. Factory executes development, GitHub owns canonical code and skills, Drive owns private business context, and Replit is the Hub runtime when applicable. Do not restart historical polling or human relay workflows.

## Output

- Goal and intended users
- Source context and current project state
- In scope and out of scope
- Pages, flows and features
- Approved copy and clearly marked copy gaps or drafts
- Design direction and reference notes
- Applicable migration and data-destination constraints
- Acceptance criteria for the bounded build
- Unresolved decisions, with their practical effect

These headings are this skill's structure, not an original vendor template. Identify what the brief does not establish. Do not claim that a prototype, installation or real integration test happened merely because a brief exists.

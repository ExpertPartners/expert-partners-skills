# Share the Love

Catch useful lessons from Allison's actual work, without making her remember to announce them. This is short agent teaching, not Book Moments, a journey journal or a course-content publisher.

## Load the playbook first

Before the first capture in a session, read the current HQ Rulebook and applicable Decision Log entries. Resolve these sources live in Drive by name and owning folder, never by a remembered ID.

- `[AG-MKT][V1.0] Share List, Bite-Sized Pieces for Agents` in AG Business Brain, Marketing. Open its content and verify its parent location. This exact existing document is the only save destination. Never rename it to match newer naming rules.
- Existing Share the Love Kits 01 through 08 in that Marketing folder, including `[AG-Marketing][V1.0] Share the Love Kit 08, Two Strikes and It's a Rule`. Read those actually available, including their notes. Report any missing kit rather than inventing its contents or treating its number as proof all earlier kits exist.
- `[AG][V1.0] Allison Gaddy Personal Brand Canon` in AG Business Brain, Company Core. Use the industry register, not the homeowner register.

Read the Share List's current structure, numbering, themes, source notes and readiness restrictions. Match its pattern. The working pattern is one useful nugget, a familiar frustration, one small move an agent can try, and the real story that earned it. Capture that seed, not a complete kit. Use Kit 08's teaching structure as an example, never copy its story onto a different lesson. The canon owns voice. Newer explicit brand rulings win where older canon conflicts.

If a source read fails, try the other available connector, API or signed-in M2 route. Say which source remains unread. Do not claim the missing source supports the lesson. If the Share List cannot be uniquely identified and read, keep the proposed capture in the current chat, say it is not saved and retain the save obligation here. Never create a replacement list or tracker.

## Notice without being asked

Stay attentive during the current conversation. After a useful build, discovery, fix, repeated correction or finished course step, ask whether an everyday agent could use the lesson in their own work. Capture a concrete reusable move, not every status update or technical detail. No timer, polling, background listener or access to other conversations is implied.

Flag a qualifying moment once in one line, exactly this shape, then save it.

`Teaching moment, <one sentence that states the lesson>.`

Do not wait for Allison to nominate it or approve the capture. Do not interrupt every turn or repeat the flag for a lesson already captured in this conversation.

When Allison says `teaching moment` or `Share the Love`, capture what was just discussed, using the nearest substantive context or her explicit reference. A request for the day's list retrieves the list instead of capturing that request as a lesson. Questions about the skill, negations such as don't capture this, quoted phrases and tool output are not capture commands. If there is no substantive context, ask one short question rather than invent a lesson.

## Write the entry

Keep her actual lesson wording when it exists. Quote only her exact words. If the lesson was demonstrated but she never phrased it, label the lesson a paraphrase from the work, not a quote or something she said. Never invent a first-person experience, result, statistic or source.

For a new lesson, number it one higher than the highest entry number already in the list, never the last number seen and never a number already used. Include these parts in the list's plain-label style.

1. The lesson in one line, in Allison's own words when available.
2. Theme, using the list's existing themes.
3. Simple version, one small action an agent can try tomorrow.
4. Why it matters to an agent, one practical benefit in plain words.
5. Story and source, what actually happened, the source date, department or workspace and chat or course step when known, and a retrievable source link when available. If no link exists, name this conversation and say no source link is available. Never fabricate one.
6. Status, captured or being proven unless evidence supports a stronger state. Preserve existing not-for-sale or confidential-course restrictions. Capture is not permission to sell or publish.

Keep it bite-sized for agents who still treat AI as search or a chatbot. Lead with the everyday job, not HQ infrastructure or software jargon. In brand writing use the live canon, first-person I only when supported by Allison's words, and its witness or teaching mode as appropriate. Allison Gaddy is the selling brand. Expert Partners is the upsell, not the narrator. Do not turn each internal capture into a sales pitch, invent an offer or quietly edit brand canon.

## Append to the one list

Read the current list immediately before writing. Compare meaning as well as wording against existing entries.

- A genuinely new lesson gets one numbered entry at the end of the list, numbered as above.
- A new source or useful refinement of an existing lesson gets a dated source note inserted directly under that entry, after its last line and after any source notes already under it, labeled Dated source note for entry N. Do not create another numbered version of the same lesson, append the note at the end of the document, or overwrite the entry's old wording or status.
- The same lesson from the same source, including a retry after a timeout, is a no-op. Read first to reconcile an uncertain write before retrying.

Write with a targeted insert, at the end for a new entry or right under the existing entry for a source note, never whole-document replacement. Preserve all previous text, formatting and entries. Use revision control when the API offers it. If another writer changes the document, reread, deduplicate and recompute the next number before appending. Never copy business content or private source URLs into the public skill repository.

Read the saved portion from the existing document. Say saved only when the appended entry or source note is there. Link the document using its exact title. A failed write stays not saved, with the proposed text and outstanding save obligation in this conversation. Capture never publishes a post, creates a kit, changes a status to sold or starts an automation.

## At the end of a working session

On session end, wrap, or a request such as today's Share List, sweep this conversation for missed qualifying moments and save them through the same append path. Then read the day's entries and dated source notes from the canonical Share List, using Allison's local date and timezone when known. Include earlier captures from other HQ conversations that are actually in that document. Do not claim to have inspected those conversations or unseen work.

Give the day's short numbered list of lessons with the Share List link. Include new-source captures under the existing lesson, once. Distinguish saved entries from any not-saved proposals. Do not reappend items just to produce the recap. If the list cannot be read, label the recap session-only and unverified against Drive. If nothing was captured today, say so briefly when a recap is requested or the session ends.

## Feed from Teach Me

At Teach Me's step-done moment, take the finished step's real output, Allison's lesson and source as input. Use this same notice, deduplicate, append and recap path. Keep the HQ guide drafts in their existing home. Do not copy confidential course material into public teaching, invent a completed step, or make the guide entry a second Share List.

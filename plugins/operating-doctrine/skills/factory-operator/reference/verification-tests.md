# Bounded preflight verification

Run deterministic tests first. Do not repeatedly spend on discovery, exhaust a limit, launch a cloud computer or treat historical M4 evidence as current. Use the existing work record for receipts.

## Before and after

Capture the existing skill's preflight fields, sequential guidance, activation events and explicit-selection behavior before the edit. After the edit compare the same contract, then run the focused hook suite.

| Case | Expected after behavior |
|---|---|
| New substantial task | Brief complexity, reasoning, duration/resources, selected route, machine and justified worker count before work |
| New small read/review/explain task | Await Skill in a separate tool step, then one-line preflight; never bundle loading with task reads |
| Routine inline work | Zero additional workers, sequential, existing context reused |
| Explicit Auto choice | Auto preserved, model alternatives advisory, hidden backend unknown |
| Missing limits or empty BYOK | Unknowns explicit, available approved Factory route not blocked |
| Conflicting older research | Newest live authority wins, no old fixed agent threshold |
| Revised scope | Fresh estimate on material change, not on every tool call |
| SessionStart | Fixed bounded routing context on startup/resume/clear/compact |
| UserPromptSubmit | Fixed reminder on possible new work, silent for common trivial replies |
| New short task | “Fix tests” and “yes, implement the module” not suppressed |
| Invalid or missing JSON | Exit success, no prompt contents logged, no unrelated hook action |
| Images without text | Reminder asks agent to assess task |
| Existing browser hook | Entry unchanged, existing route tests still pass |
| Control limits | Session fields separated from creation-time machine, defaults, Task tiers and Mission settings |

## One local native seam

After deterministic tests and capability evidence are available, run one explicitly authorized tiny M2 assignment using the supported plugin path. Inspect `/hooks` or hook transcript/debug evidence for actual registration, installed plugin version/hash and effective source. Test native discovery and a harmless preflight/read, not synthetic account exhaustion.

Use Auto and its lowest supported request effort when selected. A separately authorized pinned test is optional, never a prerequisite. Record requested and observed machine/model/reasoning/autonomy separately, reported tokens/cache/Factory counters and any missing fields. Auto request effort is not proof the backend uses that effort. Do not claim unexposed Auto backend or dollars. A hook reminder is not proof every assignment invokes Skill, and an orchestrator SendMessage may not fire UserPromptSubmit. Keep that boundary explicit.

Publication, installation, hook registration, skill invocation and task execution are separate claims. Branch-only runtime evidence is not marketplace deployment, M4 verification or certification. Use normal review/release/marketplace producers after merge approval. If a supported local branch plugin route is unavailable, report that blocker rather than copying a skill into a hand-maintained install.

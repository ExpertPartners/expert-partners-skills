# Connection First Implementation

The failure this removes is Allison operating a vendor dashboard by hand, or pasting screenshots of one, for information and actions the AI could have read or done directly. Allison's brief is the go. Get the connection and do the work.

This skill fires on the ordinary shape of her request. Configure this. Audit that. Why is this service behaving this way. Change this setting. Build against this API. Any of those, against any external service, starts here.

## The ladder

Walk it top down. Stop at the first rung that can do the job, and say which rung you landed on.

1. Connected first-party tools already live in this session. Search the tool inventory before concluding a tool does not exist.
2. Official MCP servers and connectors, installed through the supported method for this surface. First-party beats community.
3. Existing Estate integrations. The systems map lists what exists. Reuse before building a second one.
4. The official API, SDK or CLI, with credentials resolved at runtime from 1Password.
5. Browser work, last, when no programmatic path exists. It runs on Ember's M2 in the saved signed-in Chrome, never on Allison's M4.

A rung is unavailable only after a real attempt produced a real error. Report the error, not an assumption. Try the next rung before reporting a blocker. If every road is closed, name each failed attempt.

Stronger system-specific rules outrank the general ladder where they apply, such as the Drive business brains for canon, GoHighLevel through its direct API, and Firecrawl first for web data. The systems map (expert-partners-systems-map skill) is the register of what exists. This skill inherits it and does not copy it.

## Browser work

When a task is truly UI-only, runs on Ember's M2 in the existing saved Chrome with the existing 1Password integration, through the shared Playwright connector. Use the browser-automation and ember-browser-routing skills. Do not start a fresh or signed-out profile, and do not take over Allison's focus, mouse or browser on the M4. If the Ember route is down, fix or restart it yourself and carry on.

## Documentation access is not execution access

A documentation server tells you what an endpoint expects. An execution path calls it against a live account. Know which one you hold and name them separately. Docs access never stands in for account access.

## Maturity

Alpha and beta labels are evidence. When a stable official path does the same job, use it.

## Credentials

- Reuse the least-privilege credential already in 1Password. Resolve it at runtime into the consuming process, never into chat, a repository, a config file, a log or a command line.
- Use the credential that fits the job. If the scoped one lacks a permission, use another route or the right credential from 1Password and keep going.

## Prove it with a harmless read

Run a read that changes nothing, or a test that reverses cleanly, then go straight to the work. Note which resources the credential refused. Tell the failure shapes apart.

- Authorization refusal. Use a credential or route that has the permission.
- Feature not enabled on the account. Enable it if the work needs it, or say it is off.
- Wrong path. Fix the request from the vendor's live documentation.

## Setup serves the objective

Return to what Allison asked for as soon as the connection works. Do not stand up a new MCP server, repository, agent, gateway or credential store when an existing component already owns the job. Check for the duplicate first. A useful connection is made now.

## Report

Say which connection you used and its maturity, why it beat the alternatives, what it can now do directly, and links. One short note.

## Worked example, Twilio

Twilio ships a documentation-only hosted MCP server and an alpha Labs execution server. The docs server was real but gave no account access, and the alpha one was set aside because the stable REST API did the same job. Execution ran on the REST API with an existing scoped key resolved at runtime. Harmless reads proved it, and refused resources marked the credential's ceiling.

This skill inherits the operating-doctrine and never overrides it.

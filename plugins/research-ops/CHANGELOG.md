## 0.6.0 - 2026-11-03

research-intake now files each research report into the business brain that owns its subject, in the department folder it serves, named Cal's way as [Brand-Department][V1.0] Title, following Allison's ruling recorded in the Decision Log entry of 2026-11-03. The skill carries no copy of which brain owns which subject. It reads Organization Instructions, the HQ Rulebook and the Decision Log live before choosing a brain, department or subfolder, accepts a folder only inside the owning brain and owned by Allison or an Expert Partners shared drive, and moves a linked file home by its file id instead of treating it as a rediscovery, unless someone else owns it. When the owning department is unclear, the skill asks one question naming the two likeliest homes and saves nothing until it is answered. In Claude chat or Cowork it asks in chat. In Factory, Codex or Claude Code it posts the question on the board and keeps working. A title-only match counts as the report only when it is the one candidate and its content matches. Answer first, no duplicate filings, one home only and the Job Tracker row for an unruled report stay. The ADR 0045 lane tags, the Deep Research subfolder routing and the daily sweep's filing into the Deep Research folder are retired, and nothing the skill does writes into that folder.
## 0.5.8 - 2026-11-03

Source Hunter and Video Discovery now install from exact, hash-locked requirement files. Every Python package, direct and transitive, is pinned with `==` and carries its sha256 hashes, so `pip install -r` runs in hash-checking mode and refuses any package the lock does not list. The pins freeze what the earlier ranges resolved to on Python 3.12, with Pillow at one version in both skills.
## 0.5.7 - 2026-11-03

video-discovery: `video_discovery.py` and `probe_media.py` now write privacy-safe operational status events to stderr through a new `scripts/operational_logging.py` module. Each event is one JSON line holding only a fixed event name, a random run identifier, a success or failure outcome, a duration and bounded counts. Unknown fields are rejected, exception text and content are never logged, and nothing is written to files or sent over the network.
## 0.5.6 - 2026-11-03

Source Hunter joins a window title bar whose tail the OCR reads as different noise each frame, digits included. Found on the real class with anonymized fixtures, not guessed. The noise must be misread words, scraps of three letters or fewer, or words the title already shows, so a real word swapped in still splits, and a numbered slide (Week 1, Week 2) still splits when nothing else is added.
## 0.5.5 - 2026-11-03

Source Hunter joins a ticking header even when its words are misread a little from frame to frame. The live May 13 recheck after PR 199 showed the counter rule never fired, because it needed the header letters to match exactly. It now accepts them at the stitching similarity bar, only where the change looks like OCR damage, so a rewritten top line still starts a new screen.
## 0.5.4 - 2026-11-03

Source Hunter stitching now joins three more kinds of frames that belong to the screen already being built. A top line that reads the same in every frame apart from a running counter pairs with its earlier reading, at the top of the window only, so a long line lower down whose number changes still starts a new screen. A line between 21 and 29 letters long that differs only by one lone digit word, with every other word the same, counts as OCR noise, as it already did for long lines. A frame that adds nothing and only reads one line cut off, as a clean start of a line that is not a status word, joins the screen and keeps the cut reading as a variant, while a short status line that changes in place still starts a new screen.
## 0.5.3 - 2026-11-03

Source Hunter stitching now tolerates real OCR noise. A growing or repeated frame is judged by how much of the screen it keeps in order, so a few misread steady lines no longer split one screen into many. A long line that is a near miss of its earlier reading joins it, a stray digit on a long line is read as noise, and a steady line missing from one frame is kept. The other reading always stays as a variant, so no reading is lost. Short lines, and lines where one number reads as another, still mark a new screen.
## 0.5.2 - 2026-11-03

Source Hunter now stitches a chat message that grows as it streams into one screen. The pane can shift up a little, the top or bottom line can be cut off, and a spinner or status word beside the message can read differently in every frame; that changing line is kept once, with its other readings. A line that was still being typed keeps its complete reading, and a typed word that wraps to the next line is not repeated. A static slide whose title or numbered line changes still starts a new screen, even when it adds a bullet.

# Voice Guide Extractor

This is a reconstructed implementation from recovered behavior. The original May prompt after NOW BEGIN, complete schema and final save behavior are not recovered. The working schema below is ours, not a claimed transcription.

## Choose extraction or audit

Resolve company, named speaker, personal or business voice, audience register, channels and use case. Use `brand-voice` to locate current Company Core canon, approved guide, summary and calibration record. Keep identity and current brand relationships in Drive, not this skill.

If an approved calibrated guide already serves the request, reuse it or audit the requested change. Do not rebuild it because an extractor exists. Preserve accepted opener, rhythm and close decisions without asking the owner to repeat them.

Resolve source authority, date, audience scope and explicit supersession. A profile's old generic prompt is not current policy. Use the supported voice observations while excluding stale commercial, brand, hashtag or punctuation instructions. Specific audience-register rules take precedence over generic perspective advice.

For fresh personal extraction, use a fresh context outside the marketing project. In a context that cannot be isolated, return the exact fresh-context requirement and do not call the result fresh extraction. Do not use existing generated voice skills, guides or memory as raw samples. Approved guides may be comparison references, clearly labeled as such.

## Verify evidence

Read all authorized samples completely. Keep a source register with source ID, date, author or isolated speaker, channel, approval state and permitted audience. Source IDs and quotations remain in the private output, never in the public skill.

Use owner-authored writing and speaker-isolated original transcripts. Exclude other speakers, copied quotations, unattributed text and unverified AI-generated writing. Mixed transcripts require attribution before extraction. Do not infer authorship from a filename. No authentic evidence means a missing-evidence report, not a guide.

Work with the available authentic channels. The demonstrated five Instagram, five LinkedIn and three-to-five newsletter request is not a universal minimum. Spoken evidence supports spoken patterns, not invented written-channel rules. Mark missing written channels as not built.

## Extract and calibrate

Derive recognizable thinking patterns, rhythm, openings, vocabulary, tone modes, closing behavior and contextual exclusions. Cite supporting sample IDs for observations. Separate observed patterns, explicit owner decisions and tentative hypotheses. Avoid numeric confidence scores unsupported by a measured method.

Compare with existing accepted calibration. Ask only about a consequential ambiguity that evidence cannot resolve. Preserve an owner's edit with its reason, use-when, do-not-use-when and underlying thinking principle. The delta structure is a useful recovered proposal, not a mandatory original schema.

Generalize patterns instead of retaining full example emails, recurring close text, customer facts or invented deadlines. Short vocabulary evidence may be quoted privately for attribution, but do not turn example prose into reusable boilerplate. Never import Cal's, another founder's or another company's signature language.

Load `../brand-guardian/references/anti-ai-writing-guide.md` only when requested or useful for an audit. Its inclusion in a personal guide is optional. Current canon and authentic approved voice take precedence over generic editorial preferences.

## Produce two files

1. `voice-guide-full.md` contains identity and allowed scope, source register, evidence limits, observed voice patterns, supported channel sections, accepted calibration, contextual exclusions and a practical editing checklist.
2. `voice-summary-custom-instructions.md` contains one concise paragraph for the selected voice. Aim for the observed 100 to 150 words when supported, not a claimed universal Cal limit. Do not pad sparse evidence or put provenance commentary into the drop-in paragraph.

These are the reconstructed schema and demonstrated filenames. Keep missing channel evidence explicit in the full guide and delivery report. Do not call a model's self-score certification.

Create downloadable files first. If file output is unavailable, give two clearly labeled code blocks, one per file. Save new candidates in the owning company's existing output home under current document standards. Return exact-document-name links, version, source coverage, output locations and a specific update trigger. Read saved contents before claiming saved delivery.

Do not overwrite approved Company Core voice canon without a requested, evidence-backed change. Reuse existing brand skill pointers rather than creating per-founder plugins or copying private guides into the marketplace. Run `brand-guardian` against the selected canon to check downstream use. Delivery, installation and actual active use are separate claims.

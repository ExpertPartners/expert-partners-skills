# Disclosure: the `<Table Name> - <Specific Job>` worker title form is superseded by decision 0091

Filed by the worker session Startup Efficiency - Routing Simplification (a
pre-0091 dispatched title, kept as admitted), owning table Startup Efficiency,
room NORTH'S ESTATE CONTROL TOWER. This file exists because the
ruling-provenance gate requires that superseding one of Allison's rulings be
disclosed in the same commit, and because superseding a ruling is never a
silent act.

## What is superseded

The installed worker naming form. Decision 0074 (2026-08-26) ruled the worker
title `<Table Name> - <Specific Job>`, decision 0088 (2026-09-04) restated it
as the exact visible Worker title, and the installed skills carried it in
code-block-routing (routing line rule 3, Session Naming, the SESSION NAME
template, Lane Identity By Surface, the lane ledger habit, mechanic 8),
lane-spawn (v1.4 and v1.8 paragraphs, the kickoff sample, PASTE 2, Naming, the
Rules list), session-steward (section 0, section 2, the v1.4 paragraph), and
pin (v4.8 and v4.9 paragraphs, section 5 name format, the set_session_title
example). The same skills carried the room-token exception that let a worker
title grow a room prefix, and statements that a Table name is permanent for
the Table's life (decisions 0074, 0081, 0082 as installed).

Ruling of record aura decisions/0091-allison-controlled-two-word-routing-names.md.

## What supersedes it, and what does not

Superseded. Every new WORKER visible session title is exactly two clear words
identifying the job. Every new TABLE NAME and every Allison-authorized Table
rename is exactly two clear words, and an authoritative Chair's visible title
stays exactly the current TABLE NAME. Worker ownership and return identity are
carried in durable routing state, before registrar cutover the lane ledger row
and the dispatch's CLAUDE HOME line, never encoded in the visible title.
Allison may rename an existing Table by explicit direction. A rename changes
the authoritative name only, prior names remain historical aliases to the same
Table and are never reused for a different Table in the same ROOM, and only
Allison authorizes a Table rename.
Ruling of record aura decisions/0091-allison-controlled-two-word-routing-names.md.

NOT superseded. Worker self-titling at birth through the native tool, the
dispatch SESSION NAME line as the authoritative requested name (decision 0065),
chair title parity as a continuing invariant (decision 0088), the deliberate
Birth trigger (decision 0082), registrar scope admission and the pre-cutover
bridge (decisions 0080 and 0082), the wrong-door refusal law (decision 0081),
ROOM literal authority (decisions 0077 and 0084), the worker terminal
lifecycle of 2026-09-01 through 2026-09-03, and the routine-rename ban for
chats. Workers active before 2026-09-07 finish under their admitted titles and
are never renamed mid-flight. Legacy Table and Chair names are never mass-
renamed by AI; they stay legacy names until Allison explicitly renames them.

The superseded lines are marked SUPERSEDED IN PART in place inside their
version-history paragraphs and are not deleted, per this estate's
append-and-mark convention. Active rule text is rewritten to the decision 0091
reading. One adjacent conformance fix rides in the same pass: pin section 5's
flat "one table, one active worker" sentence gains its decision 0082
amendment pointer (registrar scope admission, bridge until cutover), which
lane-spawn, code-block-routing, and session-steward already carried.

## Why this landed now

The Startup Efficiency table's live audit of Worker startup cost found that
NORTH's dispatches since 2026-09-07 already carry two-word worker titles
citing decision 0091 while the installed skills still mandated the retired
form, so every new worker read two contradictory naming rules at first
contact and spent startup turns reconciling them. Bringing the installed
skills to the standing ruling is implementation conformance, not new law.

# Adding the next skill: exact steps

This is the repeatable play. Run it the same way every time.

1. Allison says: Curator, catalog the [name] skill. She pastes in the package or configuration.
2. If anything is missing (name, what it does, who owns it, the configuration), ask for it. Do not invent it.
3. Duplicate the documentation template page (live id [NOTION-ID-REMOVED]) into a new entry in the Skill Library (data source [NOTION-ID-REMOVED]).
4. Rename the new page to the skill name.
5. Fill the quick-scan properties from the configuration. Extend any select option that does not exist yet.
6. Write the full 19-section deep dive in the page body.
7. Link relations:
   - Related Skills: any sibling skills it overlaps with, depends on, or complements.
   - Related GPTs: any entries in the Custom GPT Library it builds, feeds, or complements.
   - Related Notion Database: the database it creates or manages, as a URL.
8. Run the hygiene check below.
9. Send Allison the link and a short plain-language note: what it is, how to add an entry, how to use it.

## Hygiene check

Required quick-scan fields present and sensible:
- Skill Name
- Skill Type
- Documentation Owner
- Owning Account / Workspace
- Internal Category
- Ecosystem Role
- Primary Role
- Status
- Priority
- Last Reviewed
- Plain-English Summary
- Trigger / When To Use
- Next Improvement Needed

Body check:
- All 19 sections present and filled, not left as blank labels.
- Related Skills, Related GPTs, and Related Notion Database linked where they apply.

Only mark a skill Ready for Team Use once it passes.

## When to spin off a new catalog

If Allison asks for a new kind of catalog she will clearly run again (a Workflow Cataloger, an Automation Cataloger, a Prompt Library), offer to build it as its own skill so it becomes repeatable. Build systems, not one-offs.
